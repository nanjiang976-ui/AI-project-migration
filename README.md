# AI 项目迁移助手 · AI-project-migration

[English](README.en.md) · [有什么用？](#what-it-does) · [安装](#install) · [如何使用](#usage) · [如何更新](#update) · [常见问题](#faq) · [完整指南](docs/guide.zh-CN.md)

项目盘快满了，旧聊天还要接着改文件？这个 Skill 帮你把本地项目搬到同一台电脑的另一块盘。它会核对副本，在原位置留下通往新目录的链接，并实际检查旧聊天能否读写新位置的文件。

支持 Windows 本地 NTFS 盘、macOS 本地 APFS 盘；适配 Codex 和 Claude Code，其他能执行本地命令的 Agent 可用通用流程。迁移需要 CPython 3.12+；Git 项目还需 Git。[适用环境与实测范围](docs/guide.zh-CN.md#compatibility)

<a id="what-it-does"></a>

## 有什么用？

**把本地项目搬到同一台电脑的另一块盘，让新聊天从新位置开始，也让记着旧地址的聊天继续访问项目文件。** 适合项目盘快满、项目挂了多个目录，或者已经手动搬过一部分、需要接着收尾的情况。

- **完整搬项目，核对副本。** 复制隐藏文件、空目录、未提交的代码和素材，并逐文件校验。Windows 项目内的 pnpm 依赖目录联接会映射到新位置并单独校验。遇到副本不一致、文件仍在写入或无法原样复制的内容，会指出具体问题。
- **处理多源项目和共享目录。** 在 Codex 中先列出主要源、次要源和已知的共享关系，由你选择搬哪些。同一份共享目录只搬一次，引用它的项目分别更新到同一个目标地址，各自保留原来的主次关系。
- **手动搬过或做到一半，也能接续。** 先只读检查原件、副本、项目设置、联接和聊天证据，告诉你每个来源做到哪一步，再确认剩余目录和目标位置。
- **验收旧聊天和 Git 工作树。** 逐条核对相关旧聊天能否读取、工作目录指向哪里，再挑选原聊天实际读写，确认改动落在新盘。有关联 Git 工作树时，一并核对它们与新主仓库的连接和未提交改动。
- **告诉你哪个文件夹可以清理。** 验收报告会列出新盘项目实体、旧聊天要继续使用的原名入口，以及可以手动清理的实体备份。证据不足时，会说明还有哪项待验证。

<a id="install"></a>

## 安装

选一种方式，安装在个人技能目录中，以便项目改名后仍能运行助手。

**① 把这句话发给 Agent（推荐新手）**

```text
请从 https://github.com/nanjiang976-ui/AI-project-migration 安装 skills/ai-project-migration 到当前 Agent 支持的个人技能目录。先检查是否已安装或有本地修改，再安装完整目录，核对 SKILL.md 和随附脚本，告诉我安装位置和调用方式。本次只安装，安装完成后停下。
```

Agent 需要能够访问 GitHub 并写入本机文件。仅支持聊天的网页助手请改用 ZIP 方式。

**② 用终端安装**

需要 Node.js 22.20.0 或更高版本、npm 和 Git。按你的 Agent 运行一条命令。首次使用时，npx 可能先询问是否下载 `skills` 工具。`-g` 选择个人目录，`-y` 确认安装指定的 Skill。

```sh
# Codex
npx skills add nanjiang976-ui/AI-project-migration --skill ai-project-migration -g -a codex --copy -y

# Claude Code
npx skills add nanjiang976-ui/AI-project-migration --skill ai-project-migration -g -a claude-code --copy -y
```

**③ 手动下载 ZIP**

打开 [GitHub 最新 Release 页面](https://github.com/nanjiang976-ui/AI-project-migration/releases/latest)，在 **Assets** 中选择 **Source code (zip)**。解压后把 `skills/ai-project-migration` 整个文件夹复制到个人技能目录。确认 `ai-project-migration/SKILL.md` 能直接打开，然后重开 Agent。[各宿主安装位置与目录示例](docs/guide.zh-CN.md#zip)

## 如何使用

安装后，在对应的 Agent 中发送提示词。下面以 **Codex** 为例。在 **Claude Code** 中，把开头的 `$ai-project-migration` 换成 `/ai-project-migration`。其他本地 Agent 可先读取已安装目录里的 `SKILL.md`。

### 1. 第一次用，还没确定要迁哪个项目

```text
$ai-project-migration 请引导我迁移一个本地项目。先帮我确认项目、源目录和目标位置，等我确认后再开始复制。
```

助手会先问「你要迁移哪个本地项目？」确认后会展示完整路径、迁移步骤和需要你操作的动作。迁移前会检查本机环境和源、目标盘，只在 Git 项目中检查 Git。缺少工具或版本不符时会先说明安装方式，等你明确同意并复检通过后才继续。 [迁移七步](docs/guide.zh-CN.md#steps)

### 2. 已经知道要搬哪个项目、搬到哪里

```text
$ai-project-migration 请把 Demo 的 E:\Projects\Demo 迁到 F:\Work\Demo。先核对项目配置、源目录和目标路径，再告诉我需要确认什么。
```

把示例项目名和路径换成自己的。已有目标文件夹时，助手会核对它是否属于之前的迁移，再决定怎么接续。

### 3. Codex 项目有多个源，或目录被其他项目共用

```text
$ai-project-migration Demo 有多个源文件夹。请先列出每一条完整路径、主要或次要角色，以及哪些目录被其他项目共用。让我选择本次要搬的目录和目标，再确认哪些项目需要一起更新。
```

只想迁一个次要源时，可以补一句「保留原来的主要目录」。即使这个次要源只由当前项目使用，也走批次流程。验收时，可在从主要目录启动的原聊天里，保持默认工作目录，通过次要源的旧路径双向读写新位置的文件。选中共享目录时，助手会先列出受影响的项目，等你确认同步范围。

### 4. 已经手动搬过，或上次迁移做到一半

```text
$ai-project-migration 我已经手动搬过一部分，迁移还没做完。请先只读检查原件、目标、副本、旧入口、项目配置和聊天状态，告诉我每个目录做到哪一步、下一步是什么。剩余目录和目标由我确认。
```

已有检查点时，助手会和现场对照，从能够核实的步骤接续。缺少原件或校验记录时，会说明哪些结论还需要补证。[中途接续检查](skills/ai-project-migration/references/resume.md)

### 5. 已建立联接，重开后要验证旧聊天

在**迁移前就存在的那条聊天**里发送以下提示词。

```text
$ai-project-migration 联接已建立。请先核对它指向正确的目标，然后从本条旧聊天的默认工作目录验证实际读写，确认改动落在新盘，并清理测试文件。
```

涉及共享目录时，还要分别确认相关项目的旧聊天都能访问对应来源。报告会区分历史可读、路径可达和实际读写。

### 6. 迁完了，想确认能否清理旧备份

```text
$ai-project-migration 请做最后复核，分别报告项目文件、旧聊天和 Git 工作树的验收结果。列出必须保留的原名入口、新盘实体和可手动清理的备份完整路径。
```

**⚠️ 请保留原位置下的原名入口。** 旧聊天通过它访问新盘。验收通过后，可以手动清理报告指明的 `_迁移备份` 实体目录。

<a id="update"></a>

## 如何更新

**正在迁移项目时，请先完成当前迁移，再更新 Skill。** 离线命令可能仍在使用已安装的脚本。按当初的安装方式更新即可：

- **CLI 安装**：重新运行[上面对应 Agent 的安装命令](#install)，保留 `--skill ai-project-migration` 和原来的 `-a` 参数。这样只更新这个宿主里的这一项技能。若你手动修改过技能文件，先备份改动。
- **Agent 安装**：把这句发给 Agent：“请从 https://github.com/nanjiang976-ui/AI-project-migration 更新我已安装的 ai-project-migration。先核对安装位置、安装方式和本地修改，更新同一份技能，验证调用入口后停下。”
- **ZIP 安装**：下载新版 ZIP，先将已安装的文件夹暂存到技能目录之外，再把新版完整复制到原安装位置。重开 Agent 并按上面的方式检查入口；如曾自行修改，先比较并保留改动。

> [!CAUTION]
> **⚠️ 请勿删除原位置下的原名文件夹。** 它是旧聊天访问新项目的入口。请放心，保留这个入口几乎不占用硬盘空间。进入其中删除文件会直接影响目标盘上的项目。只有最终验收通过后，才可手动清理报告指明的 `_迁移备份` 实体目录。

<a id="faq"></a>

## 常见问题（FAQ）

### Codex 项目有多个源文件夹，需要先移除其他来源吗？迁移共享目录时，其他项目会一起更新吗？

保留原有的源列表，先选本次要搬的目录。只迁本项目独有的主目录时，共享来源可以留在原位。假设 `Demo` 把 `SharedAssets` 设为次要源，`AssetLibrary` 把同一目录设为主要源。若确认迁移这份共享目录，只复制和校验一次，然后分别将两个项目的对应条目指向同一个新路径，各自保留原来的主次角色。Codex 按项目保存源列表，编辑其中一个项目时，其他项目仍需分别同步。

Skill 会在复制前列出来源和共享范围。只迁一个次要源、迁多个实体目录，或迁一个共享目录并同步其引用项目，都走批次流程。全部副本校验通过后，批次先接好旧路径，再逐项目换源和回读。已有单目录迁移从原检查点接续。[Codex 多源批次手册](skills/ai-project-migration/references/batch.md)

### 怎样腾出原盘空间，同时让相关旧聊天继续访问迁移后的文件？

验收通过后，手动清理原盘的实体备份。保留原名入口，也就是 Windows 的目录联接或 macOS 的目录符号链接，旧聊天仍可通过原地址访问目标盘。逐条核对相关旧聊天的原 ID、历史和工作目录，再从每个受影响项目中选择代表性旧聊天，对其涉及的已迁目录实际读写。报告分开记录逐条核对的数量和实际读写的范围。只要目录或聊天仍待核验，就保留对应备份。
