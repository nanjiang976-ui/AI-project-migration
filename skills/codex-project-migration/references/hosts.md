# 宿主适配与会话证据 / Host adapters

先确认**执行助手**和**旧聊天所属宿主**。文件复制、Git、原名入口可以由具有本地权限的助手执行；聊天归属、恢复和默认工作目录由原宿主证明。一次迁移绑定同一台主机、源实体和目标卷，不迁移账号、远程会话数据库或其他电脑的记录。

## Codex 桌面

- 个人安装位置通常为 `~/.agents/skills/codex-project-migration/`；保留已经能被当前环境识别的安装位置，避免重复注册。调用 `$codex-project-migration`。
- 读回原项目 ID，按 [聊天验收手册](chats.md) 分页收集适用的历史与工作树基准。换源后再次核对同一 ID、主要目录、其他源和原分组；能读出同一回合并不证明写到了目标目录。
- 直接在合适的旧聊天里使用其默认 cwd。跨聊天仅向用户明确选定并授权的那一条发送一条可见消息，登记请求编号，重开时先检查相同请求的回执。

### 绑定一次旧会话读写请求（各宿主共用）

核实选定的是迁移前原会话后，先生成请求 UUID，将原会话在所属宿主中的可核实标识填入下面的两个参数。如果只能核实文件路径，使用文件系统诊断或记为待验证，不把迁移编号当作宿主身份。

```text
run_record.py mark --run RUN --step 6 --status waiting --request-id UUID --session-id ORIGINAL_SESSION --evidence "已核实基准、目标会话和用户的发送方式" --next-action "在选定的旧会话中运行探针"
probe.py --plan RUN/cutover-plan.json --request-id UUID --resumed-session-id ORIGINAL_SESSION
run_record.py mark --run RUN --step 6 --status passed --request-id UUID --session-id ORIGINAL_SESSION --evidence "宿主确认同一原会话，已读取本次双向回执" --next-action "复核聊天、工作树和备份"
```

第一、三条在迁移流程中运行。第二条必须在选中的旧聊天执行，命令不指定工作目录。真实宿主身份由外部会话证据确认，脚本负责绑定请求、身份声明和文件读写回执。任何一项不匹配都保留备份。

## Claude Code 本地 CLI

- 个人 Skill 放在 `~/.claude/skills/codex-project-migration/SKILL.md`。在本地 Claude Code 输入 `/codex-project-migration`。用户也可让其他执行助手引导 Claude 的迁移。用 `--host claude-code` 创建迁移运行记录，项目没有桌面项目 ID 时留空。
- 迁移前，在用户选定的一条原主目录会话中记录**宿主给出的会话 ID**和原目录；获准时同时记录该会话原始 transcript 的绝对路径作恢复后备。只记录选定会话所需元数据，避免读取或外传无关正文。文件系统测试前记录请求 UUID。在临时测试项目中，可用 `claude --session-id <新 UUID>` 创建独立测试基准。
- 文件复制通过后，从新的实体目录打开 Claude Code，核对新会话实际默认目录。CLI 的这个动作对应桌面产品的换源；无需虚构“编辑项目”菜单。离线改名前退出正占用项目的 CLI、终端或编辑器，从独立终端运行该次命令。
- 建好原路径入口后，从原项目地址尝试 `claude --resume <原会话ID>`。部分旧版本只在当前目录所属项目及其工作树内检索，宿主可能把旧地址解析为目标目录。如果找不到，使用支持的 `claude --resume <该会话原始.jsonl的绝对路径>`，或在宿主的恢复选择器中选择并核实原 ID。使用原始记录的路径只作为 Claude 官方恢复参数；不要改写或搬运聊天库。恢复时不要使用 `--fork-session`。只保留“按 ID 当前不可见”的阶段结果，直到确实恢复并核对同一 ID。
- 从该会话默认目录调用探针 `probe.py --plan <本次计划> --request-id <已登记UUID> --resumed-session-id <已核实的原ID>`。同时核对 Claude 宿主回报的 ID、执行的请求、磁盘探针回执及备份隔离；传入一个 ID 字符串不足以证明会话恢复。物理 cwd 等于目标目录时可以通过，前提是原会话身份、旧名入口、文件身份和双向读写都已核实。获取不到新会话或历史清单时明确列出范围。
- 真实模型调用可能消耗用户额度。代发、登录、模型或费用授权按当前环境和用户选择处理，CI 只使用虚构离线数据，不放个人授权信息。[Claude Code Skills](https://code.claude.com/docs/en/skills) · [CLI 会话恢复参数](https://code.claude.com/docs/en/cli-reference)

## 通用本地 Agent

| 能力 | 可执行的动作 | 应报告的覆盖范围 |
|---|---|---|
| 读取 Skill 文件并运行本机命令 | 由用户给出源和目标绝对路径，按七步调用同一组助手 | 文件复制、Git、链接可以独立核验 |
| 有工作区或项目设置 | 使用宿主支持的入口更新同一项目；也可引导用户从目标目录打开新会话，核对实际默认位置 | 记录真实宿主标识或人工确认的范围；`migration_id` 仅识别本次搬迁 |
| 有旧聊天但无法列举或代发 | 用户在原宿主手动选择迁移前的会话，粘贴已绑定请求的提示词并带回回执 | 单列该条原会话可核实的身份依据；无历史接口写“历史未能批量核验” |
| 无法确认原会话/默认目录 | 可显式使用 `probe.py ... --filesystem-only` 核对两条本机路径 | 标记步骤 6 为 `unverified`，实际完成的旧会话数记零，保留备份；不能用“没有接口”推断“没有历史” |
| 已有完整基准，确实没有可测试的主目录旧会话 | 步骤 6 可登记 `not_applicable` 并记录依据 | 最终表写明原有工作树或其他类别、实际测试数零 |

没有跨聊天消息接口时，把手动提示词交给用户，不尝试内部数据库、远程接管或假装发送。连本地命令也无法运行时，该 Agent 仅可提供人工引导，并逐项列出未实测内容。
