# 聊天、项目和实际读写的验收

## 步骤 1 · 以原项目为基准

通过桌面项目列表读取项目 ID、主目录和主机。多源项目另从“编辑项目”或其受支持的配置读取入口确认完整目录列表，记录顺序和哪个是主目录。多源项目的标准流程只迁移所选项目的主目录，保持其他源及彼此顺序。如果用户明确要迁移次要源，列出它与主目录的区别，单独规划如何保持原默认目录，暂不套用主目录切换命令或探针。

用桌面的 `list_threads` 对同一 Codex 主机分别分页读取未归档和归档历史（`mode=history`、`source=codex`、`limit=50`，跟随每页 `nextCursor`）。覆盖置顶的相关聊天，按聊天 ID 去重，保留下列类别：

- 明确绑定原项目 ID 的聊天。
- 未返回项目归属、但工作目录精确匹配原主目录或已登记工作树的聊天。单独记录，不凭同名、标题或字符串前缀认定归属。
- 标明归档状态、主目录或各独立工作树、非主目录或无法确认的路径。如果有主项目子目录聊天，记录其确切相对位置、单列覆盖。选主目录探针时用根目录精确匹配的旧聊天。

通过 `read_thread` 按原 ID 做只读历史基准，优先 `turnLimit=1, includeOutputs=false, maxOutputCharsPerItem=0`。检查返回 ID、是否含一个真实历史回合，空聊天另记；仅将 ID、类别、可读性、cwd、归档和项目归属写入本次运行目录下的 `chats-before.json`。标题由桌面读取并原样用于用户选择。不要把聊天正文、命令输出、凭据或全账户无关记录写入报告。记录实际覆盖页数、不可访问项和失败原因。如果当前环境没有所需读取接口，请用户在原侧栏核对可见历史；只报告实际核到的范围。

## 步骤 4 · 看见保存结果

优先在原项目里完成“编辑项目 → 添加文件夹 → 选择已校验的目标完整路径 → 设为主要 → 移除本次旧目录条目 → 保存”。始终核对完整路径；两个目录的显示名通常相同。保留其他源。若出现新路径的信任提示，核对到**本次目标项目**再按当前权限处理。红色的“移除本地项目”会影响项目分组。界面不可控时，给用户这些确切点击步骤。回读同一个项目 ID 和实际根配置，未保存成功就停在本步。没有公开的项目根写入接口时，不替用户直接改历史、SQLite 或内部配置。

正常情况下新建本地聊天以主目录启动。报告里区分“主路径已回读”和“新聊天已实测”。如用户还要求新聊天实测，由用户打开新的本地聊天（或明确授权创建），在其默认工作目录读取路径。工作树聊天有独立目录。

## 步骤 6 · 联接确认后才出现的选择

先运行手册中的 `cutover.py status` 并确认 phase 为 `linked`。根据基准筛出主目录旧聊天，优先找可继续使用且空闲的聊天。未归档、切换前即存在、旧 cwd 符合和属于正确主机是常用选择依据。当前聊天如不符合，给出候选标题和可区分的 ID；不要为了测试而恢复归档或打断其他正在执行的任务。

为本次测试生成一个 UUID。给用户提示词或跨聊天发送之前，先把选定聊天 ID、UUID、方式及预期回执路径 `RUN/probe-<UUID>.json` 写入步骤 6 的 waiting 检查点；在提示词的探针命令中显式传入 `--request-id <UUID>`。当前聊天自测也使用相同方式绑定回执。中断后先查同编号回执和目标聊天是否收到测试消息；若确实发过就续等，无法判断时先向用户确认，不重新发送。只有预先选定的聊天 ID、请求编号、计划路径和证据都吻合时，才计为本次实际读写。

**A．你手动发送。** 先给出候选并确认用户要使用的旧聊天，登记该 ID 与 UUID，再用绝对 Skill 路径和绝对运行目录生成下方提示词，替换全部方括号。请用户贴进选定的旧聊天，完成后回到迁移聊天告知结果。先检查已登记位置的本机回执及选中聊天的测试记录；仍缺证据时，只索取无法自行核到的部分。

**B．Codex 自动验证。** 当前就在基准中的旧主目录聊天时，直接用其默认工作目录运行探针。否则先让用户选择具体旧聊天，并当场说明“是否同意我向《实际标题》发送一条可见的读写测试消息？”获得该指定聊天的明确授权后，才可用 `send_message_to_thread` 发送下方提示词。一次发送一条；已发送则续等，不因超时重复发送。使用 `wait_threads` 跟踪具体目标和游标，必要时用 `read_thread` 核对结果。若该版工具不可用，转为选项 A。选择自动模式本身不构成向任意聊天发送消息的授权。

> 请在这个旧聊天**本身的默认工作目录**运行一次 Codex 项目迁移验收。不要设置执行工具的 workdir，不要 cd 或使用另一条聊天代测。已核实的目标目录是 [真实 D 盘项目完整路径]。请直接执行 [已填好脚本绝对路径、--plan 与 --request-id 的 python -B 命令]。它会独占创建随机测试文件，从 D 盘核对内容和文件身份，再从 D 盘追加、回到旧路径读回，仅清理这一个测试文件。请在本聊天返回默认目录、双向读写结果、清理状态及本次 JSON 回执完整路径。如果默认目录或身份不符，请报告实际值并停止。

探针须在被选中的旧聊天里从**默认目录**发起。当前迁移聊天通过显式指定旧路径运行的 shell，只能证明路径连通性。读取本次运行目录中的新回执，核对所属计划、旧路径和实际目标、双向读写、文件身份及清理。将发起探针的聊天 ID、手动/自动方式、授权或用户转述、回执路径记入步骤 6。若完整基准确认没有符合条件的旧主目录聊天，记步骤 6 为 `not_applicable` 并允许进入最终复核，实际测试数记录为 0，分别报告联接可用性和已有聊天类别。基准不完整不能当作没有聊天。若有合适聊天但未获授权或无法完成验证，保留为待处理项。

## 步骤 7 · 最终聊天报告

重新分页并按原 ID 读取。输出原项目分组保留数、基准总数和可读数（区分归档、未归档和仅路径关联），另列本次新增、无法读取或归属改变的聊天。单列实际完成双向读写的旧聊天标识和数量；读取历史和实际写文件是两项独立证据。将结果写入本次运行目录，不在用户旧聊天中批量发消息，不把本机运行记录带入 Skill 发布包。
