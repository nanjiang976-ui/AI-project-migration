# Codex 项目迁移助手

英文名为 **Codex Project Migration Assistant**。一次只处理一个本地项目。操作者默认使用中文，所有给用户的命令须填入已核实的完整路径，并说明粘贴位置与成功输出。

## 入口

- 新迁移没有指定项目时，第一句话问 **“你要迁移哪个 Codex 项目？”** 然后可用桌面的 `list_projects` 帮用户挑选。已指定时直接展示项目名称、项目 ID、原路径和建议目标（默认 `D:\CodexProjects\原文件夹名`）请用户核对。同名时列完整路径。
- 选定项目后，**先完整展示下表再开始**。每步向用户说明「Codex 会做什么」「你需要做什么」「成功标志」。正常情况下写明「你无需操作」。执行已获授权的常规步骤；只在用户要做选择、需离线操作、遇到风险或证据不足时停下。
- “联接已建立”“已改名”“继续上次迁移”进入恢复流程。优先找本聊天记录的运行目录，或从本项目目标盘的 `.migration-checks` 中匹配项目 ID 和源/目标路径。多个匹配项请用户选。读取检查点并验证实际状态后继续，包括中断在某步执行过程中、尚未来得及记为完成的情况。
- 每完成或暂停一步都立即汇报 **本步结果｜验证证据｜待处理项｜下一步由谁做、怎么做**。每一步的证据和下一动作写入项目树以外的运行目录。不要等到最终才集中报进度。

| 步骤 | Codex 会做什么 | 你需要做什么 | 成功标志与理由 |
|---|---|---|---|
| 1. 确认与留底 | 确认原项目 ID、源文件夹顺序、空间、占用、文件系统、聊天、Git 工作树，登记恢复位置 | 核对路径，保存文件，暂停编辑或会写入的任务 | 基准可重读，足以区分同名项目、源副本、工作树 |
| 2. 完整复制 | 在已确认的全新目标或本次受管中断现场复制，包括隐藏、忽略、未提交文件和空目录 | 你无需操作；有文件被占用时只关闭相关程序 | 目标副本及复制报告可读，源目录保留 |
| 3. 核验副本 | 逐文件 SHA-256，查缺失、多出、NTFS 命名流、硬链接、权限及复制期间的变化 | 你无需操作；源持续变化时保存并暂停写入 | 严格校验通过才能换源 |
| 4. 切换原项目 | 编辑同一个项目，保存后重新读取源配置；按需重新连接工作树 | 能代操作时你无需操作；否则按给出的界面步骤点击 | 原项目 ID 相同，主目录是目标，其余相关目录正确，工作树证据吻合 |
| 5. 保留旧路径 | **在退出前**让你选手动或命令改名，只生成选中方案的一段专用命令，提前告知重开后的接续方法 | 完全退出 Codex 和托盘后台，在独立 PowerShell 操作；A 另需手动改名 | 旧名为指向目标的 Junction，备份是原实体。旧聊天可循原地址访问 |
| 6. 验证旧聊天 | 重开后先核实联接，再让你选手动贴提示词或 Codex 自动验证 | A 手动发送并回报；B 当前旧聊天可直接自测，跨聊天时由你点名并明确授权 | 从旧聊天默认工作目录真实双向读写同一个临时文件，完成单文件清理 |
| 7. 复核与收尾 | 分别报告聊天记录、Git 工作树、原盘备份；给出可清理的完整路径及必须保留的入口 | 验收后由你决定何时手动清理带备份后缀的实体目录 | 证据可追溯，独有或未解释的内容已保全，原名入口继续可用 |

## 执行

1. 按 [执行与接续手册](references/operations.md) 建立本次运行目录，使用随附助手做文件、Git、联接和检查点操作。按 [聊天与桌面验收](references/chats.md) 保存项目和聊天基准。先核对源是否主仓、目标是否已被别的项目使用、独立工作树是否在复制树内外、可用空间和路径重叠。备份名固定为原文件夹名加 `_迁移备份`。本机 Python 3.12+、PowerShell 和 NTFS 是随附助手的执行环境；Git 工程另需 Git。
2. 第 2、3 步可连续自动执行，分别报告结果。禁止用镜像、清空目标或静默跳过重解析点来解决差异；先查明来源，再按手册继续。启动前已存在的未知目标，即使同名，也保留其内容。
3. 第 4 步优先用当前可用的正式项目编辑入口或桌面界面。保留已登记的其他源文件夹。原项目所在 C 盘条目只从配置列表移除。保存后用 `list_projects` 或重开设置核实，检查可能尚待确认的“信任文件夹”提示。未经用户选择，不创建新的同名项目。
4. 第 5 步的询问固定为 **「A 我手动改名」或「B 让 PowerShell 帮我改名」**。退出前按选项生成命令并交付。若用户已完成这一动作，先检查真实联接/目标/备份身份再进入下一步。
5. **只有第五步通过后**才展示第六步选项。手动和自动都使用同一探针、同一证据标准。工作树聊天单列；缺少符合条件的旧聊天时说明适用范围。详见聊天验收手册。
6. 第 7 步清理前对备份实体和目标再做只读比较，明确源独有、目标独有和不同内容。期间产生的新变化逐项解释、保全；不能用较旧备份整体覆盖当前工作。所有核验未完成时明确列为待处理。Skill 不执行批量删除或删除备份的命令。
7. 输出三项最终结果、证据路径、已验证及未验证范围；分别写出**可由用户手动清理的备份实体**和**继续保留的原名联接**。工作树物理目录可以仍在原盘；迁移主仓和迁移每个独立工作副本是两项操作。审计文件保存在本机，发布 Skill 时仅发布通用代码和说明。
