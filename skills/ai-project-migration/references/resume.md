# 中途接续检查

项目已手动搬过、另一个迁移任务暂停、旧版先处理了多源项目的一部分，或开始时发现目标已经存在，都先核对现场。**检查只读取当前配置、已知目录、记录和聊天证据。** 先完成可做的只读核对，再按[阶段汇报与接续](../SKILL.md#阶段汇报与接续)告知每份来源已完成的动作、尚待验证的事项及下一步的执行方。仅在剩余迁移范围仍未确认时请用户确认，再按原流程接续。

## 先读实际配置与记录

1. 在原宿主核对项目 ID 和完整源列表，记录主要、次要角色。Codex 的项目简表常常只有主要目录。取不到全表时，请用户在原项目的「编辑项目」读回，标记清单未完整。搜索共享来源时采用同宿主上能核查的项目清单。
2. 读取当前聊天已记录的运行目录、用户给出的证据路径，或已知迁移审计位置中与本项目相关的记录。按宿主、项目 ID、原/目标路径匹配。多个候选无法区分时请用户选定。保留原单目录和批次记录格式。
3. 记录能实际核实的会话 ID、项目归属、当前返回的工作目录、历史可读性和归档状态。只保留元数据。无法列全时标记未完整；旧聊天原 ID 可读、工作目录可解析和真实读写回执分别报告。独立工作树单列，按真实 Git 基线核对。
4. 旧地址与新地址同时列在项目配置时，先对照是否来自同一次迁移的记录和证据。只因目录同名或都存在，就应把对应关系留待确认。不要重新复制已验证的目标或从旧源覆写目标上的工作。

## 运行只读检查

先按[迁移环境预检](preflight.md)确认本机系统、终端和 Python。仅检查下一步所需的位置和工具，使用已核实的实际目标或备份实体。检查器读到已有 Git 基线并可核实目标 Git 仓库时，会尝试验证工作树。涉及这类 Git 检查时，先对这些实际仓库执行接续环境预检并加 `--git-root`。依赖暂时不可用时可继续只读核对宿主和记录，按实际证据标注待核项。

对于能回读项目来源的本地 Codex，从项目以外的目录执行，使用脚本及两个输入文件的绝对路径。输入可存到已有的本机私有审计区。以下示例使用虚构项目。报告输出到 stdout，检查器本身不改文件、项目设置或聊天。若实际宿主无法提供这些项目资料，则按[宿主手册](hosts.md)逐项核对可见路径和旧会话，说明证据缺口。

```text
resume_check.py --snapshot PROJECTS.json --input INSPECTION.json
```

`PROJECTS.json` 使用 [批次手册](batch.md)的宿主配置形状（`version: 1`、`host_id`、`complete`、含 `id`、`name`、`sources` 的 `projects`）。只有实际回读完整时才设置 `complete: true`。下面是 `INSPECTION.json` 的例子：

```json
{
  "project_id": "demo",
  "sources": [
    {"source": "E:/Example/Demo", "target": "F:/Example/Demo"},
    {"source": "E:/Example/Assets"}
  ],
  "records": ["F:/PrivateMigrationChecks/demo-prior-run"],
  "history_complete": false,
  "sessions": [
    {"id": "example-chat", "project_id": "demo", "cwd": "E:/Example/Demo", "history_readable": true, "archived": false}
  ]
}
```

`sources` 可以略去，先列实际配置和能匹配的记录。可按来源提供旧地址、已确认的目标和需要核对的 `backup`。未知目标不填，让检查器先提出问题。 `records` 只列精确的已知批次或单目录运行目录，避免扫描无关项目。提供 session 时使用真实宿主校验结果，未取得的部分留待核实。

用户说明已手动搬迁且未找到匹配记录时，先确认原地址和现在的目标，特别是项目只显示新地址的情况。用这对路径做检查，再给出接续建议。

## 按来源解释报告，再继续

| 观察 | 下一步与执行方 |
|---|---|
| 原件在、目标未指定 | 请用户选择剩余要搬的目录和目标完整路径。助手核对共享项目及原角色。 |
| 原件和目标都在 | 助手匹配已有凭据和真实路径，对未证实副本单独比对内容和权限，保留目标上的新改动。 |
| 主要目录已设为目标，旧源配置还在 | 助手回读完整来源，按原单目录或批次顺序接续。到换源步骤时，只移除本次迁移的旧路径条目并保留其他来源。确需用户在界面操作时给出项目和具体条目，保存后由助手回读复核。 |
| 原地址已空出，有可确认的备份或目标 | 助手区分备用实体和来源记录，先确认可核实的目标。原件身份或完整性仍无法复核时，列出缺项及恢复旧路径所需的证据。 |
| 原地址已经是正确链接 | 助手复核真实目标、项目配置、原聊天历史及读写证据，继续处理能补齐的验收。 |
| 链接指错或断开，备份身份不明，检查点和现场冲突 | 助手保留现场，先用现有记录核实身份。仍有歧义时，请用户确认具体路径、候选或所缺证据。 |

报告中的旧校验是记录过的证据。继续前按现有流程重新验证相关文件内容、权限、Git 工作树和旧入口。没有可信原件或旧审计时明确报告完整性待核。此入口不出具备份清理许可，等待标准单目录或批次的最终验收。旧版已为多源项目建立单目录记录时，先从原记录收尾，再为其他已选来源准备新批次。
