# AI 项目迁移助手

英文显示名为 **AI-project-migration**，安装目录和调用标识为 `ai-project-migration`。一次迁移一个本地项目。按用户的语言沟通。为用户生成的离线命令必须填好实际路径，同时说明在哪个终端运行及预期输出。

安装或更新应使用个人技能目录，放在待搬项目之外。正在迁移或已经发出离线切换命令时，请先完成当前迁移，再更新同一份 Skill。[安装与更新说明](https://github.com/nanjiang976-ui/AI-project-migration#update)

## 入口和恢复

- 新迁移未指定项目时，第一句话问 **“你要迁移哪个本地项目？”** 已指定时，先识别执行助手及其能力，展示项目名称、实际源路径和用户选定的目标完整路径。目标未知就请用户选择目标盘和文件夹；不得假定特定盘符、项目父目录或 Agent。若旧聊天可能属于另一个平台，再确认要保留哪个宿主的会话。
- 按[宿主适配](references/hosts.md)获取实际可用的项目/历史入口。同名项目列完整路径供选择。记录能核实的宿主项目标识；宿主不提供稳定项目 ID 时使用本次迁移编号，注明来源。分别记录执行助手和旧会话归属。
- **Codex 在第 1 步、复制前先核对「编辑项目」中的完整源文件夹列表。** 有多个源时，列出完整路径、主要或次要角色和已知共享情况，主动问本次迁移哪一条或哪几条，保留未选项。如果项目简表只给了主要路径，请用户核对完整清单。选中共享源时先列出引用项目，确认是否一起同步。选多份实体或涉及多个引用项目时，使用 [Codex 多源批次](references/batch.md)；同一实体只搬一次。
- 项目选定后，**完整展示下表，再开始实施**。每步说明「助手会做什么」「你需要做什么」「成功标志」。正常情况写明「你无需操作」。每完成或暂停一步立即汇报 **本步结果｜验证证据｜待处理项｜下一步由谁做、怎么做**。
- “已改名”“联接已建立”“继续上次迁移”进入恢复流程。读取匹配的运行目录和原检查点，对照真实路径、实体、配置及宿主，多个匹配项请用户选。原单目录记录按原流程接续。批次用 `project_batch.py status` 核对已完成目录与项目，避免重复改名、发消息或修复。

| 步骤 | 助手会做什么 | 你需要做什么 | 成功标志与理由 |
|---|---|---|---|
| 1. 确认与留底 | 核对源盘和目标盘的系统标识、路径、可用空间、占用、项目及聊天基准、Git 状态和运行目录 | 核对路径，保存并暂停写入；若在同一个盘内移动，另行确认 | 身份与可验范围明确；在同一个盘内移动不能为这个盘腾出空间 |
| 2. 完整复制 | 复制到全新目标或本次受管候选，保留源、隐藏文件和空目录 | 通常无需操作；按需关闭占用者 | 目标实体及本次复制证据可读 |
| 3. 独立校验 | 逐文件 SHA-256；核对目录、硬链接、权限、文件系统元数据、源稳定性 | 通常无需操作；源仍变化时保存并暂停写入 | 严格比较通过才切换 |
| 4. 使用新位置 | 按所属宿主切换原项目或从目标打开新会话，回读配置或核验实际默认目录，按需连接工作树 | 接口不足时按具体提示操作 | 新工作使用目标；项目身份、历史和工作树核验范围如实记录 |
| 5. 保留旧路径 | **退出前**让用户选手动改名或命令改名，只生成选中方案并交代预期结果 | 退出占用项目的 Agent/程序，从独立 PowerShell 或 Mac 终端操作；手动模式需先改名 | 原名为直达目标的 Windows 目录联接或 macOS 目录符号链接；备份仍是原实体 |
| 6. 验证旧会话 | 重开、核对入口后才让用户选手动贴提示词或自动验证；分别检查原会话身份、默认目录双向读写和旧路径 | 手动转交并回报，或使用已确认的旧会话；向指定聊天代发需明确授权 | 宿主证据与本次探针回执吻合；无法验证的项目单列 |
| 7. 复核与收尾 | 复核聊天、工作树和原件备份，展示三条完整路径和醒目警示 | 验收后自行决定是否手动清理实体备份 | 旧入口继续可用，备份独有或未解释的数据得到保全 |

## 执行要点

1. 单目录按[执行与接续手册](references/operations.md)登记，按[聊天与桌面验收](references/chats.md)保存基准。Codex 批次按[多源批次手册](references/batch.md)的顺序，全部副本通过后先接好原名入口，再逐项目换源，最后仅按批次验收判定备份。两种流程均支持同机、同一操作系统内的本地盘，Windows NTFS 或已挂载可写的 macOS APFS；需 CPython 3.12+，Git 项目另需 Git。通过系统标识判断是否跨盘；同一硬盘的两个分区可以是两个盘。
2. 第 2、3 步可以连续自动执行，但分别报告。出现文件变化、未知目标、访问权限、外部硬链接、意外链接或名称碰撞，按证据停止并保全；不递归删除、镜像清空或覆盖已有用户项目。
3. 第 4 步按旧聊天所属宿主执行。Codex 保留原项目 ID、所选源的主要或次要角色和其他源目录；Claude Code 与通用 CLI 在目标处验证新会话的实际默认目录。不能控制界面时由用户操作。不要复制聊天数据库或直接编辑宿主私有历史来声称已恢复原会话。
4. 第 5 步给 **A 我手动改名 / B 让命令帮我改名**，退出前仅给用户所选的一段命令。备份是原名加 `_迁移备份`。重开后核对源、目标、备份和原名链接身份。
5. 第 6 步给 **A 我手动发送 / B 助手自动验证**。原会话所属宿主确认身份后从该会话默认目录测双向读写。有真实会话基准且仅目录显示已解析/重绑时可传原 ID；纯文件系统诊断独立标记。没有批量历史接口即报告“历史未能批量核验”。外部工作树聊天按其真实目录单列。
6. 第 7 步在备份实体和目标之间重新比较。查看已完成记录、再次询问清理时，均先按实际核验状态展示下面的警示，**替换三个占位符为完整路径**。使用 `run_record.py show` 的最新清理提示。若自报告后有新写入，应先重新复核。

   > **⚠️ 请勿删除原位置下的原名文件夹：〈旧路径〉**
   >
   > 这里是 Windows 目录联接或 macOS 目录符号链接（只写本机实际类型）。旧聊天通过它访问新地址。删除入口会使旧路径失效；**进入其中删除文件会直接影响目标盘上的项目文件。**
   >
   > **正在使用的项目实体，必须保留：〈目标路径〉**
   >
   > **验收通过后可手动清理的实体备份：〈备份路径〉**

   核验未完成、备份含独有文件或存在未解释差异时，最后一行改为 **⛔ 暂勿清理备份：〈完整备份路径〉**，列明缺口。Skill 不执行备份或整棵目录清理。公共发布只包含通用代码和手册，本机运行记录留在本机。
